數位典藏庫可在哪裡下載注音資料的 METS 2.0 與 PREMIS 3.0 套件？

使用不依賴 App 的移轉套件，透過 METS 2.0 檔案清單與結構圖，加上 PREMIS 3.0 保存 metadata，將全部 37 個注音符號送入數位典藏庫 staging。

簡短回答

Deterministic ZIP 包含十個成員：mets.xml、premis.xml、雙語 README、CC BY 4.0 標示檔、五個可重用資料檔，以及 checksums-sha256.txt。METS fileSec 以相對路徑、IANA media type、byte size 與 SHA-256 列出七個保存檔案；logical structMap 將資料與文件分組，且每個檔案都恰好被指向一次。METS 2.0 mdRef 連結完整的外部 PREMIS 紀錄，不使用 METS 2 已移除的 XLink。PREMIS 記錄七個 File Object，其原始名稱、格式、大小與 fixity 均一致；另含一個成功的 metadata-creation Event、publisher 與 generator 兩個 Agent，以及連結每個 Object 的一份 CC BY 4.0 Rights statement。兩份 XML 都使用固定至不可變公開 source commit 的官方 XSD byte snapshot 進行離線驗證。套件也會檢查全部路徑、digest、37 列 CSV、37 筆 JSON Lines、ZIP 順序、固定 timestamp 與 file mode。此 ZIP 是 deterministic transfer wrapper，不是 METS 定義的封裝格式。套件沒有 DOI，也不宣稱已登錄或匯入典藏庫、通過第三方認證、獲機構背書或具有數位簽章。

下載 ZIP 與 checksums-sha256.txt，驗證外層 ZIP digest，在不變更相對路徑的情況下解壓縮，再以所引用的官方 XSD 版本驗證 mets.xml 與 premis.xml。匯入典藏庫前，請確認全部七筆 METS file entry、七個 PREMIS File Object、Event link 與 Rights link 都符合解壓縮後的 bytes。

挑選前要注意什麼

  • 標準 37 列 CSV 與語意相同的 JSON Lines，完整涵蓋 U+3105 至 U+3129
  • METS 2.0 fileSec、logical structMap 與外部 PREMIS 3.0 mdRef，不依賴 XLink
  • 七個 PREMIS File Object、一個 generation Event、兩個 Agent 與一份 CC BY 4.0 Rights statement
  • 使用固定官方 bytes 的 METS 2.0 與 PREMIS 3.0 XSD 進行離線驗證
  • 包含十個成員的 deterministic ZIP，附逐檔與外層 SHA-256 checksum

實用的決策步驟

  1. 開啟雙語套件指南，下載 ZIP 與 checksums-sha256.txt。
  2. 解壓縮 transfer wrapper 前，先驗證已發布的外層 SHA-256。
  3. 使用所引用的精確官方 XSD 版本驗證 mets.xml 與 premis.xml。
  4. 將每個 METS file 與 PREMIS Object 的路徑、media type、byte size 及 SHA-256，逐一與解壓縮後的 payload 比對。
  5. 匯入前，請檢查 PREMIS Event、Agents、Rights statement 與本地典藏庫政策。

常見問題

METS 是否內嵌 PREMIS 紀錄？

不是。mets.xml 使用 METS 2.0 mdRef，並記錄 LOCREF=premis.xml、PREMIS 3.0 版本、media type、byte size 與 SHA-256。解壓縮後，兩個檔案仍位於同一層。

此 ZIP 是 METS 定義的封裝格式嗎？

不是。METS 描述套件的檔案清單與結構，但未定義此 ZIP serialization。這個 ZIP 只是 deterministic transfer wrapper，另有公開的外層 SHA-256。

Schema 驗證能證明典藏庫已匯入或內容真實性嗎？

不能。XSD 驗證與 checksum 只能確認結構與 fixity，無法證明外部典藏庫已匯入、機構背書、第三方認證、真實性或數位簽章。
