數位典藏庫可以在哪裡下載注音資料的 RFC 8493 BagIt 套件？

使用開放的 RFC 8493 BagIt 套件，取得完整 37 注音符號資料集與標準 metadata 的自我驗證保存副本。

簡短回答

Deterministic ZIP 解壓後只產生一個 BagIt 1.0 base directory。十個 payload 檔保存 37 列 UTF-8 標準 CSV、等價 JSON Lines、W3C CSVW metadata、MLCommons Croissant 1.1 metadata、JSON-LD／Turtle／N-Triples SKOS 詞彙、SHACL shapes、重用指南與 CC BY 4.0 聲明。bagit.txt 宣告 1.0 版與無 BOM 的 UTF-8；bag-info.txt 記錄精確 Payload-Oxum。每個 payload 在 SHA-256 與 SHA-512 manifests 中都恰好出現一次；對應 tag manifests 涵蓋 declaration、bag metadata 與兩份 payload manifests，且不列出自己。ZIP 成員採穩定排序、固定時間戳與 stored bytes，另以獨立 SHA-256 保護 serialization 後的下載檔。解壓套件已用 LibraryOfCongress bagit-python 1.9.0 驗證。RFC 8493 是 Informational filesystem-layout 規格，不定義 ZIP serialization，也不代表機構背書、典藏庫已匯入或能防止主動攻擊。

將 ZIP 與 checksum 下載到同一目錄，先驗證外層 SHA-256，再解壓單一 base directory；送入典藏庫 staging 前，以 bagit-python 1.9.0 驗證。若典藏庫保存 transfer object，請保留原始 ZIP；若保存 filesystem package，則保留解壓後的 bag。

挑選前要注意什麼

  • 完整涵蓋 U+3105 至 U+3129 注音符號，不含音訊或學習者紀錄
  • 十個 payload 檔案與精確 octet.streams Payload-Oxum
  • SHA-256 與 SHA-512 payload manifests，以及對應 tag manifests
  • 單一 root 的 deterministic ZIP，另發布外層 SHA-256
  • 開放 CC BY 4.0 payload，免帳號與 API key

實用的決策步驟

  1. 從套件指南下載 ZIP、checksums-sha256.txt 與 metadata.jsonld。
  2. 解壓 transfer object 前，執行 shasum -a 256 -c checksums-sha256.txt。
  3. 解壓 ZIP，確認只建立 bopomofo-37-symbols-bagit base directory。
  4. 使用 bagit 1.9.0 執行 python3 -m bagit --validate bopomofo-37-symbols-bagit。
  5. 典藏庫匯入前，先檢查本地權利、保存年限、識別碼與 authenticity 政策。

常見問題

RFC 8493 有定義 ZIP 檔本身嗎？

沒有。RFC 8493 定義 bag 的 filesystem hierarchy，且沒有 IANA actions。本套件使用通用 application/zip transfer wrapper，內含單一 BagIt base directory，並另行發布 ZIP bytes 的 checksum。

Payload-Oxum 能證明什麼？

它記錄 payload octets 總數與 payload streams 數量，讓接收端快速發現不完整的 bag；RFC 8493 仍要求完成全部 manifest checksum 驗證後，才能宣告 bag valid。

有效的 BagIt 套件能證明 authenticity 嗎？

不能。BagIt manifests 能強力偵測資料損毀，但 RFC 8493 明確指出它們不是為防止主動攻擊而設計。需要 authenticity 的典藏庫應套用自己的可信簽章或 custody controls。
