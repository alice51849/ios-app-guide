Linked Data client 可在哪裡將注音複製為 LDES 1.0 與 TREE 事件流？

從穩定且不依賴 App 的 JSON-LD EventStream IRI 開始，再走訪三個 immutable TREE node，為每個標準注音符號複製一筆第一版事件。

簡短回答

此套件依循官方 LDES 1.0 consumer specification、vocabulary、server primer 與 TREE hypermedia specification。Canonical JSON-LD entry point 同時是 ldes:EventStream 與可更新的 root tree:Node，且只有一個指向自身的 tree:view。它將 ldes:timestampPath 設為 dcterms:created、ldes:versionOfPath 設為 dcterms:isVersionOf，並公開 version-create class、inline SHACL member shape，以及 ldes:startingFrom 等於首筆保留事件的 retention policy。六筆具型別 TREE relation 為三個 JSON-LD node 建立成對的含下界與不含上界 dcterms:created 範圍。每個 node 都標示 ldes:immutable true 並內嵌自己的 tree:member 描述。37 個唯一 member IRI 包含具時區 timestamp、連至穩定 SKOS concept IRI，並重現 U+3105 至 U+3129 的 canonical CSV 欄位。Turtle 檔是連至 canonical JSON-LD root 的 discovery overview，不宣稱伺服器端 content negotiation。包含九個成員的 deterministic ZIP、SHA-256 清單、雙語重用指南與 CC BY 4.0 聲明支援離線驗證。每份 JSON-LD 都使用 inline context，並測試所有 RDF graph、relation 邊界、來源 concept、checksum 與 ZIP 屬性。此發布者自行建立的靜態快照不宣稱提供即時寫入 API、自訂 Cache-Control header、registry 登錄、外部複製、認證或 LDES／TREE 社群背書。

開啟 JSON-LD entry point，確認一個指向自身的 tree:view，並讀取 timestamp、version 與 shape path。沿時間篩選無法剪枝的 tree:relation／tree:node 配對走訪，擷取事件流的 tree:member IRI，驗證 dcterms:created 與 dcterms:isVersionOf，並保存已 emit 的 member IRI。離線檢查時，先驗證 checksums-sha256.txt 再開啟 deterministic ZIP。

挑選前要注意什麼

  • 一個穩定 ldes:EventStream 與 root node，且恰有一個指向自身的 tree:view
  • 37 個 immutable 版本 member，涵蓋每個標準注音符號
  • 三個 JSON-LD TREE node，具有成對的 dcterms:created 上下界
  • 明確的 timestampPath、versionOfPath、create 語意、retention policy 與 SHACL shape
  • Turtle discovery overview、deterministic bundle 與 byte 層級 SHA-256 驗證

實用的決策步驟

  1. 開啟雙語指南並記錄 canonical JSON-LD EventStream IRI。
  2. 解析 root，並確認 TREE view、timestamp path 與 version path。
  3. 沿六筆有邊界的 relation 走訪三個 immutable node。
  4. 每個唯一 TREE member 僅 emit 一次，並驗證全部 37 個 SKOS version target。
  5. 驗證 SHACL path，並在下次同步前保存 member state。

常見問題

LDES client 可以從 Turtle 檔開始嗎？

可以。Turtle overview 有一筆 tree:view 連至 canonical JSON-LD root。此發布不宣稱支援伺服器端 content negotiation；client 會沿明確連結前往 JSON-LD node。

為什麼三個 member node 都標示為 immutable？

LDES member 是 append-only；官方 client algorithm 可避免重新擷取明確標示 ldes:immutable true 的頁面。任何不相容的未來修訂都必須使用新的版本化 node IRI，不可改動這些 bytes。

這能證明其他 registry 或 client 已複製事件流嗎？

不能。這是可公開 dereference 且通過內部驗證的靜態發布；不宣稱已登錄 registry、由第三方複製、取得認證或社群背書。
