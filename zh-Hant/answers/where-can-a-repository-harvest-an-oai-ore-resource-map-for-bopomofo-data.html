典藏庫可在哪裡採集注音資料的 OAI-ORE Resource Map？

使用不依賴 App 的 OAI-ORE aggregation，將十六項注音資料、詞彙、schema、API 與事件流資源發布為邊界明確的有限複合數位物件。

簡短回答

此套件以不同的 protocol-based URI-R 發布三份 Resource Map：權威 RDF/XML、Turtle 與 JSON-LD map。三者描述相同 URI-A 與十六成員 Aggregation Graph。URI-A 在 RDF/XML URI 後加上 #aggregation，遵循 OAI-ORE 無伺服器 hash-URI 實作；client dereference 時移除 fragment 即可取得 Resource Map，不需要 303 redirect 或 content negotiation。每份 map 都恰有一筆 ore:describes，標示發布 Agent 與修改 timestamp，透過 ore:isDescribedBy 公開三份 map，並列出相同 ore:aggregates 邊界。成員涵蓋 canonical JSON、CSV、JSON Lines、Croissant、CSVW、SKOS JSON-LD／Turtle／N-Triples、SHACL、Frictionless Data Package、Table Schema、靜態 API index、OpenAPI 描述，以及 LDES JSON-LD entry point 與 Turtle discovery overview。每項資源都記錄 media type、byte size、反向 ore:isAggregatedBy 與具名 SPDX SHA-256 checksum。所有 serialization 均獨立解析為 RDF、檢查 connectedness 與 ORE 結構，並比對實際發布 bytes。六成員 deterministic ZIP 收錄三份 map、雙語 README、CC BY 4.0 聲明與 checksum 清單。JSON-LD 是額外現代 RDF serialization，不宣稱為 2008 年原始 OAI-ORE profile，也不宣稱獲 OAI 背書、已由外部典藏庫匯入、具有 DOI、通過第三方認證、支援 content negotiation 或符合 Atom。

開啟雙語指南，解析 RDF/XML Resource Map 或下載 deterministic ZIP，驗證 checksums-sha256.txt，再將各 map 解析為 RDF。送入典藏庫 staging 前，確認每個 URI-R 都描述已發布 hash URI、三份 map 公開相同的十六個 ore:aggregates object，且每個 byte size 與 SHA-256 都符合實際擷取資源。

挑選前要注意什麼

  • 一個 hash-URI Aggregation，精確表示十六項注音資源
  • RDF/XML、Turtle 與 JSON-LD Resource Map 使用不同 URI，但具相同 Aggregation Graph
  • 必要的 creator 與 modified metadata，以及 ore:describes、ore:isDescribedBy 與 ore:aggregates 連結
  • 每項資源均附 media type、byte size、反向 membership 與 SPDX SHA-256
  • 包含六個成員的 deterministic ZIP，附雙語驗證指南與 checksum

實用的決策步驟

  1. 開啟套件指南，記錄 RDF/XML Resource Map 與 #aggregation URI。
  2. 下載 Resource Map 或 bundle，並驗證 checksums-sha256.txt。
  3. 使用支援 RDF/XML、Turtle 或 JSON-LD 的 RDF library 解析各檔案。
  4. 確認每份 map 都只有一個 ore:describes target，且具有相同的十六個 ore:aggregates member。
  5. 匯入前擷取每個成員，並比對其 media type、byte size 與 SHA-256。

常見問題

為什麼 Aggregation URI 以 #aggregation 結尾？

OAI-ORE 為不支援 303 redirect 的靜態 host 記載 hash-URI 模式。Client dereference 時會移除 fragment、取得 RDF/XML Resource Map，再區分概念性的 Aggregation 與 Resource Map URI。

三份 Resource Map 使用相同 URI 嗎？

不是。OAI-ORE 要求每份 Resource Map 使用不同 URI。每份 map 都描述同一 Aggregation，並公開相同的十六成員 Aggregation Graph，同時保留各 serialization 專屬的 Resource Map metadata。

JSON-LD 是 OAI-ORE 1.0 原始 serialization profile 嗎？

不是。OAI-ORE 將 Resource Map 定義為 RDF Graph，並指出可用任何 RDF syntax serialization；但其 2008 年實作文件直接 profile 的格式包括 RDF/XML 與 Atom。此處將 JSON-LD 作為額外的現代 RDF serialization，不宣稱它是 OAI 原始 profile。
