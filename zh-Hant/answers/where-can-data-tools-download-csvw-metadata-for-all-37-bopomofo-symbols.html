精準解答

資料工具可以在哪裡下載涵蓋全部 37 個注音符號的 CSVW 中繼資料？

使用開放的注音 CSVW 資料包。它將一份涵蓋全部 37 個標準符號的 UTF-8 標準 CSV，與遵循 W3C 表格資料 Recommendations 及 CSVW 預設探索檔名的中繼資料配對。

簡短回答

CSV 含 37 列資料與 12 個欄位，分別記錄順序、穩定符號 ID、概念 IRI、符號、Unicode 表示、漢語拼音、概略 IPA、分類、分類 IRI 與例字欄位。相鄰的 zhuyin-bopomofo-ml-dataset.csv-metadata.json 文件會先載入官方 CSVW context，宣告 UTF-8 逗號分隔格式與一列標題，將每個欄位設為必填、以 symbol_id 作為唯一主鍵，並提供資料型別、facet、BCP 47 語言標籤、列主體 URI 模板及 RDF property 或 value mapping。確定性 ZIP 包含 CSV、中繼資料、README、CC BY 4.0 聲明與 SHA-256 清單。固定且未修改的官方 JSON-LD context 與 Turtle 詞彙快照支援離線詞彙檢查，發布的配對檔案亦通過 csvw 4.1.0 驗證。W3C 定義此格式，但未認證或背書本資料包，也未確認任何外部工具或目錄已完成匯入。

將中繼資料下載到 CSV 旁，或解壓縮完整 ZIP；先驗證校驗碼，再對中繼資料檔執行 csvwvalidate。不同工具對 CSVW 功能與遠端 URL 的處理方式不一，請測試實際下游處理器。

挑選前要注意什麼

  • 完整涵蓋 Unicode U+3105 至 U+3129：21 個聲母、3 個介音與 13 個韻母
  • 12 個必填欄位，使用 integer、string、anyURI 資料型別及明確 facet
  • 唯一 symbol_id 主鍵、穩定 SKOS 列主體，以及 RDF property 或 value mapping
  • 採用標準 <CSV URL>-metadata.json 探索名稱，並以相對 URL 指向相鄰 CSV
  • 確定性 ZIP、CC BY 4.0 標示、精確對應 bytes 的 SHA-256，且免帳號

實用的決策步驟

  1. 下載完整 ZIP 供離線使用，或將中繼資料檔放在標準 CSV 旁。
  2. 使用 csvw 4.1.0 執行 csvwvalidate zhuyin-bopomofo-ml-dataset.csv-metadata.json。
  3. 確認處理器回報 37 列、12 個欄位，且沒有主鍵或資料型別錯誤。
  4. 產生 RDF 前先檢查 aboutUrl、propertyUrl 與 valueUrl mapping。
  5. 驗證 SHA-256，並在發布前於測試環境檢查目標 ETL 或資料目錄。

常見問題

CSVW 工具如何自動探索中繼資料？

中繼資料以 zhuyin-bopomofo-ml-dataset.csv-metadata.json 發布在 CSV 旁，遵循標準 <CSV URL>-metadata.json 探索名稱，並以相對 url 指回相鄰 CSV。

每個 CSV 或資料目錄工具都會以相同方式匯入 CSVW 嗎？

不會。各工具支援的 CSVW 功能、URI template 行為與遠端 Content-Type 要求不同。請驗證中繼資料並在測試流程中使用實際處理器，不要假設普遍相容。

這個資料包經 W3C 認證或背書嗎？

沒有。它以已發布的 W3C Recommendations 為準，並對照固定的官方詞彙快照檢查；但 W3C 未認證或背書本資料集，也未確認外部系統已匯入。
